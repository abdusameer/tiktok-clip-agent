# /make-rankings (unattended local production)

Arguments: `$ARGUMENTS`

Forms: `--url <youtube-url> --rights <note>` · `<video>` · `--video V [--audio A] [--transcript T] [--rights <note>]` · `--source-id <id>` (reuse a stored source, nothing is downloaded or analyzed again). Only videos the user owns, has permission to use, or is otherwise authorized to process; a YouTube URL needs `--rights` BEFORE anything is downloaded.

Setup for every shell call: `export PATH=/opt/homebrew/bin:$PATH` and run the CLI as `PYTHONPATH=src .venv/bin/python -m clipagent.cli <cmd>`.

## Unattended mode (the standard behaviour)
Starting this command authorizes the whole local workflow. Do NOT ask the user questions, request choices, confirmation, review or approval, and do not stop for intermediate approval. When something is uncertain (a candidate, title, timestamp, wording or format) apply the rules below; if it still cannot be verified, skip that item and carry on. If one output fails, record it and keep processing the others. Finish with exactly one final report, then stop and wait for the next command.
Only genuinely unrecoverable setup failures (`doctor` fails, the source is unusable, rights note missing for NEW media) end the run early - report them in the final report instead of asking.
This command authorizes only: local analysis/rendering, filing into `approved/` or `needs-review/`, registering moments, and recoverable (Trash) cleanup of allowlisted run files. It never authorizes uploading, publishing, spending credits, purging a source, deleting finals/permanent records, or touching anything outside the project/selected run.

## Hard rules
- Style source of truth: `config/ranking_style.json`. Never approximate or redesign the template; render only through `clipagent render` (ranking) or `clipagent render-standalone` (standalone).
- Editorial policy is canonical in `CONTENT_EDITING_RULES.md` (read it first; it overrides anything below). A ranking has as many honest entries as fit one narrow theme (minimum 3, never padded; no 4-5 quota); a standalone video has exactly one moment. Never pad a weak video to reach a count or duration; drop it and say why. No fixed cap on the number of videos.
- Never install software, spend Higgsfield credits, upload, publish (publicly or to drafts), purge a source, delete originals/finals, or overwrite any output/prior render. TikTok transfer stays a separate user-authorized command.
- Profanity stays exactly as spoken. No bleeping.
- Rank and title are stored separately (`{"rank": 4, "title": "KSI Bad Breath"}`); never put `#4` in a title. The rank must equal the clip's badge, its sequence position and the countdown (first clip plays the highest rank, last clip is #1). The label pill shows the title only because the badge is the one visible number; `titles.label_text` yields `#4 KSI Bad Breath` for manifests/QA.

## Source library (built in)
Every source lives once at `source_library/<source-id>/` (`master.mp4`, `source.json`, `transcripts/`, `analysis/`, `fingerprint/`). States: `active`, `exhausted`, `archived`, `purged`.
- **New media** (`--video V [--audio A]`): run `ingest-source --video V [--audio A] --rights "<how the user is authorized>"` (ask the user for the rights note). It validates both files, checks the durations are compatible, builds a temporary master (video stream-copied, AAC audio copied or - only if needed - encoded), verifies streams/sync/decode, then links it in as `master.mp4`. It never overwrites a different master.
- **Identity is by content, not filename/encoding/SHA-256.** If the media matches or partially matches an existing source's audio probes the command exits with code 2 and `STOP - ask the user`: ask whether it is the same source or a new one (only then re-run with `--new-source --identity-note "..."`). Never associate silently.
- **Reuse** (`--source-id <id>`): `source-status <id>` shows what is missing; reuse the stored master, transcript and analysis; regenerate ONLY missing items into the library (`transcribe`/`merge-transcripts`/`analyze` write into `source_library/<id>/`). Then `prepare-run --source-id <id>` (no re-combining).
- **Lifecycle:** `set-source-status <id> active|exhausted|archived`; mark `exhausted` when no worthwhile unused moments remain. `purged` is only set by the PURGE SOURCE flow, and an `active` source can never be purged.
- **Never reuse a moment across finished videos.** (A ranking and a standalone from the same run may share a moment only as the recorded, materially different reuse defined in `CONTENT_EDITING_RULES.md` section 6.) Before selecting, and in `check-plan <plan> --source-id <id> [--run-id <run>]`, every moment is checked against the permanent registry and active-run reservations: overlap, boundaries within ~5 s of a used exchange, identical/substantially similar transcript (also across different sources, re-downloads, re-encodes), and reservations. Include each moment's `text_sha256`/`sketch` (see `registry.text_fingerprint` / `registry.sketch`) in the plan. Different moments by the same creator/topic are NOT blocked; the same source may yield many different videos. Reserve chosen moments with `registry.reserve` while a run is in progress and `registry.release` if abandoned.

## Formats
Choose the best format per moment automatically; never invent another visual style.
- **Ranking** (3+ moments sharing one narrow theme): approved template with header, countdown chips, big badge, label pill and the "wait for #1" hook. `render`.
- **Standalone** (one complete scene): same crop, blurred backdrop, safe margins, audio treatment and caption handling, but NO ranking graphics. Use when one moment has a strong hook, understandable context and payoff. `render-standalone`. Spec: `{"title": ..., "moments": {"1": {start, end, words, lines}}}`; title 2-5 words (stored, used for the manifest/cover, not drawn).
- **Durations are content-driven and never a rule.** Each moment lasts exactly as long as its setup, action/dialogue, payoff and valuable reaction need. There is no minimum, maximum, warning or target for a moment or a video (no 5/17/30/60/90 s figures); runtime is only recorded in the manifest. The sole duration check is the platform's technical upload limit (`limits.video_platform_max_seconds`); above it, split only at a natural story/scene boundary. Never cut off words or reactions, speed footage up, remove necessary context, add filler or reject an otherwise strong video for its length. Resolution, codec, sync, duplicate-prevention and the visual template are unchanged.
- **Classify every candidate before assigning formats.** After analyzing ALL candidate moments of the source, label each one: `ranking` (works best as one entry in a countdown of 3+ honest same-theme moments), `standalone` (strong enough to carry its own video: strong hook, understandable context, payoff, one complete scene) or `rejected` (weak, unclear, duplicated, incomplete or risky; record the reason). Keep the classification in `runs/<id>/candidates/classification.json`.
- **Order of work:** build the strongest ranking videos first, but do not consume a moment that would clearly perform better as a standalone. Then inspect EVERY remaining unused candidate and automatically make standalone videos from all that still pass the quality requirements. Never turn weak leftovers into standalones just to raise the count. A moment is never reused or overlapped between formats. Continue until no strong unused moments remain, then `auto-cleanup` and stop with the report.
- Allocation: give each moment to whichever format yields the strongest finished video. Never bury an excellent standalone moment inside a weaker ranking. Keep going until every remaining unused moment is weak, unclear, duplicated, risky or cannot form a good video. Never lower the threshold or pad to raise the count. Every moment is used at most once across ALL outputs (registry + run reservations + `check-plan`).

## Workflow (runs start to finish with NO questions, NO intermediate plans shown, NO approval gates)
The user's only expected result is completed ranking videos that passed QA and are ready to transfer into TikTok drafts. Show nothing mid-run; do not wait for anyone.
1. `doctor` (stop and report if a required tool is missing; never install).
2. **Validate and ingest the source.** `prepare-source --url <u> --rights <note>` | `--video V [--audio A] --rights <note>` | `--source-id <id>` resolves the input into ONE canonical `source_library/<id>/master.mp4` (YouTube: `deps` first - yt-dlp/ffmpeg/ffprobe are never installed automatically, report what is missing; `youtube-info` records id, URL, title, duration, chapters and captions; the download only happens with the authorization note; combine, verify and ingest via the existing system). Identity matches stop with exit code 2. `--source-id` must be `active` (set it `active` for the run if only `exhausted`, set it back at the end if nothing worthwhile is left). Any 16:9 source (720p, 1080p, 1440p, 4K...) is mapped by normalized ratios; an unusual aspect ratio still renders (uncropped fit) but that output goes to `needs-review`. `prepare-run --source-id <id>` creates `runs/<run-id>/`.
3. Log the Higgsfield balance only via the free `balance` tool if available; never call a generate tool.
4. **Detect every existing clip segment and analyze the whole video** (never from a web page, title, description or transcript alone): `analyze-source <id>` inspects the media, uses supplied/manual captions else a local transcript, detects scene changes AND classifies each cut as a camera-angle change within one continuing event (allowed) or an unrelated scene (blocked), extracts frames and contact sheets across the whole video, OCRs on-screen text, measures audio/motion and writes `source_library/<id>/{transcript.json, transcript.srt, analysis.json, frames/, contact-sheets/, candidates.json}` (reused when it already exists for the master; `--force` redoes it). Candidates carry exact bounds, transcript excerpt, on-screen text, scene-cut quality, context risk, signals and 5 phase frames.
5. **Score and visually review.** Open the contact sheets and each candidate's phase frames (Read the images), also read the whole transcript for missed moments, then `apply-reviews <id> reviews.json` (`visible_action, works_without_context, hook, setup, payoff, audio/visual confidence, suggested_format, rejection_reason, viewed_frames`). Anything the frames cannot confirm is uncertain -> skipped. No transcript-only selections (`check-plan` refuses unreviewed/rejected candidates).
6. **Check the permanent used-clips registry and select the strongest unique moments** (registry, reservations and `check-plan --source-id <id> --run-id <run> --scan-chat` enforce no reuse/overlap, evidence, no unrelated scene change, and no severe language in visible chat). Give each moment the span its setup, complete dialogue/action, joke and payoff need - length is never a criterion. Create as many strong rankings (3+ honest entries each) as the source supports and run the standalone pass on everything else; both passes are mandatory. Never pad. Skip uncertain candidates and continue.
7. **Severe language in the footage or visible chat** (slurs, hateful/discriminatory attacks; ordinary profanity stays uncensored): `scan-chat <id> --start --end` samples the whole frame throughout the moment. Trim to the suggested clean span when possible; otherwise reject the candidate (or the finished video goes to `needs-review`). Chat too small to read in the 1080x1920 output is recorded as unverified, never as clean.
8. **Generate categories, ranks and titles** (unique 2-5 words, casual, specific, Title Case, only verified names; rank stored separately, rank = badge = position = countdown).
9. **Verify the selected moments and write captions from evidence only.** `decode-moment <id> --start --end --out d.json` gives two independent decodes; build caption lines ONLY from `suggested_lines` (words both decodes confirm) and keep both decodes in each moment's `decodes`. `render` refuses wording that is not confirmed (omit the word or adjust the boundary).
10. **Render** each video with `render` (ranking) / `render-standalone` to `runs/<id>/renders/<name>.mp4` (new names only). Title-text accent colors are assigned automatically (palette + contrast checked before rendering, seeded by run id + video id, recorded in the spec, a `.render.json` sidecar and the manifest). Generated titles, captions and hashtags are scanned for severe language before rendering.
11. **QA + automatic correction.** `finalize-video` runs full QA. On a fixable failure (frozen/black frames at the very start/end) apply `production.fix_hints` (trim) and re-render under a NEW name, at most 2 retries per video, then finalize again. Passing videos go to `approved/<run-id>/` with their manifest, QA report, caption, cover title, hashtags, text colors, duration, `status: ready_for_draft_transfer`, `approval: auto_qa_approved` (never "manually reviewed") and their moments are registered as used. Anything that still fails or is uncertain goes to `needs-review/<run-id>/` (not registered); the run continues with the other videos.
12. Update `usage.json`. `auto-cleanup <run-id> [--source-id <id> --inputs]` releases reservations and moves ONLY allowlisted run-specific temp files (and verified separate input copies) to the macOS Trash; it skips everything if any video was not stored safely and leaves files in place if the Trash is unavailable. Never `rm`.
13. Set the source `exhausted` if no worthwhile unused moments remain. Print `production-report <run-id>` as the ONE final report (completed videos, durations, categories, output paths, assigned text colors, used clip IDs, QA status, cleanup result, remaining unused candidates, protected source, errors/warnings). Then STOP and wait for the next command.

## Completion boundary
Authorized without asking: local processing, automated QA, filing into `approved/`, registry updates, recoverable Trash cleanup of allowlisted run files. NOT authorized: Higgsfield credit spending, external uploads, TikTok transfer (the finished videos are only marked ready_for_draft_transfer), public publishing, permanent deletion, canonical-source purging.

## Always preserved
Every approved final, the canonical `master.mp4`, source transcript/analysis/metadata/fingerprints, the permanent used-clips registry, unused-moment history, manifests and QA reports, project code/skills/tests/config, reusable models/fonts/assets. Never purge a source; never permanently delete; never operate outside the project or selected run.

## Title accent colors
Only the title-text fill of each ranked label varies (`config/ranking_style.json` -> `label.title_accent`): one solid color per ranked title from the approved palette (#FFD84D, #58D9FF, #8BE36B, #FF9F43, #FF7EB6, #C9A7FF, #FFFFFF), no repeat on consecutive ranks, contrast >= 4.5:1 against the label background (else another palette color, else white). Font, size, badge, label background, placement, animation, safe margins, crop and blur are unchanged. No gradients, per-letter colors or flashing.

## Used-clips registry
`registry/used_clips.json` permanently records every ranked moment of each finished video (source sha256, start/end, rank, title, transcript fingerprint). It survives `/deleteandcleanup`. When planning, pass the source's full sha256: `check-plan plan.json --source-sha256 <sha>` so moments already used are rejected. After a video is finished, register its moments with `clipagent.registry.register` before any cleanup; `/deleteandcleanup` refuses to remove transcripts/sources until the registry holds them (records with `registry_required`).
