# /make-content (unattended)

Arguments: `$ARGUMENTS`

Forms: `--video <path>` · `--video <path> --audio <path>` · `--source-id <id>`. Once invoked this runs start to finish: NO questions about clips, categories, titles, boundaries, colors or formats; NO intermediate plans or approvals. When uncertain apply the deterministic rules, skip the candidate, send an uncertain render to `needs-review/` and keep going. `/make-rankings` stays available for ranking-only production; do not create other commands.

Setup for every shell call: `export PATH=/opt/homebrew/bin:$PATH`; CLI: `PYTHONPATH=src .venv/bin/python -m clipagent.cli <cmd>`.
Never: upload, publish, transfer to TikTok, spend credits, install software, permanently delete, purge a source, or touch anything outside the project / this run. Moving allowlisted temporary files to the macOS Trash is allowed.

## Layout (one clean structure)
`source_library/<id>/{master.mp4, source.json, transcript/, analysis/{timeline.json, segments.csv, candidates.json, rejected.json, contact-sheets/, thumbnails/}}` · `runs/<run-id>/{STATUS.md, status.json, ingest/, segments/shortlisted-previews/, plan/, working/{rankings,funny-moments,continuous-moments}/, qa/{reports,frames}/, logs/, usage.json}` · `ready-for-drafts/<source-id>/<run-id>/{index.html, summary.json, rankings/R01-<name>/, funny-moments/F01-<name>/, continuous-moments/C01-<name>/}` (each: `<ID>-<name>.mp4, cover.jpg, caption.txt, manifest.json, qa.json`) · `needs-review/<source-id>/<run-id>/<output>/`. Filenames are descriptive (`R01-funniest-reactions.mp4`); hashes live in manifests. One canonical `master.mp4` per source, never copied.

## Workflow
1. `doctor` (report, never install). `content-start --source-id <id>` or `--video <path> [--audio <path>]` -> prints the run id (new media is ingested into one master; identity matches stop with exit 2). STATUS.md/status.json now track the stage: INGESTING -> ANALYZING -> CLASSIFYING -> PLANNING -> RENDERING -> QA -> ORGANIZING -> CLEANING -> COMPLETE (or FAILED).
2. `content-segment <run-id>`: full analysis (reused if present), then segment detection. The source is usually an edited compilation: every hard cut is scored; a camera-angle change inside one continuing event (same palette, ambience/level, speech across) does NOT split a segment; a real clip boundary does. Every second of the timeline is a segment or a rejected section with a reason (`timeline.json`); `segments.csv` lists ID, times, description, transcript, visible action, boundary confidence, humor score, context score, format, rejection reason, used-clip match; each segment has a 3-frame strip in `analysis/thumbnails/` and contact sheets in `analysis/contact-sheets/`. If very few segments come out of a long compilation a second coverage pass runs automatically.
3. **Classify (visual review).** Read `analysis/contact-sheets/segments_*.jpg` (and each strip/frame when needed), then write `reviews.json` and run `apply-reviews <source-id> reviews.json`. Every segment gets exactly ONE format: `ranking` (several short moments sharing one truthful category), `funny` (one complete short joke/reaction/roast/payoff), `continuous` (one longer scene needing setup, escalation, payoff) or `rejected` (weak/unclear/duplicate/incomplete, with reason). Per review: `visible_action, hook, setup, payoff, works_without_context, audio_confidence, visual_confidence, viewed_frames (>=3 own frames), title` (ranking: unique 2-5 words; funny/continuous: truthful 2-6 word headline), `category` (rankings; meaningfully different categories, e.g. Funniest Reactions, Most Chaotic Moments, Wildest Conversations), optional `use_start/use_end` to trim to the shortest complete span (never start mid-word, include setup and the reaction/payoff). Scores prioritize candidates; they never automatically delete an understandable funny moment. Do not consume an excellent standalone moment inside a weaker ranking. Skip unverifiable candidates (set `rejected` with the reason) - never ask.
4. `content-plan <run-id>`: builds every strong ranking possible (4-5 moments, countdown to #1, unique titles), then funny and continuous videos from the remaining eligible segments; writes `plan/{rankings,funny-moments,continuous-moments,rejected}.json`. The permanent used-clips registry is checked; no moment is reused, overlapped or placed in two formats. Ranking moments are normally ~5-17 s, funny ~5-25 s, continuous ~15-90 s (guidance, not limits); videos may exceed one minute; no filler.
5. `content-render <run-id>`: per moment, two independent decodes (captions contain ONLY words both decodes confirm) and a whole-frame chat scan (severe slurs/hateful language block the moment; ordinary profanity stays uncensored; unreadable chat is recorded as unverified), then renders into `working/<format>/`. Rankings use the approved template; funny/continuous use the same crop, blur, font, label background, safe margins, audio and caption handling with only the headline pill (no badge). ONE seeded accent color per finished video (approved palette, contrast-checked, white fallback).
6. `content-finalize <run-id>`: technical, cut-boundary (no cut inside a spoken word), audio-sync, caption, label/headline, crop/framing, duplicate, text-safety and template QA; edit points are checked. Passed videos go to `ready-for-drafts/.../<format>/` with `status: ready_for_draft_transfer` (never "uploaded"/"published") and their moments are registered as used; failed/uncertain ones go to `needs-review/`. A fixable failure (frozen/black frames or a cut inside a word at an edge) -> adjust `use_start/use_end` in the review, re-plan only that video and re-render under a fresh name (max 2 retries); then continue. Sloppy cuts must fail QA.
7. `content-clean <run-id>`: moves ONLY allowlisted temporary files (working renders and caches, shortlisted previews, QA frames, sampled evidence frames) to the Trash; preserves the master, transcript, timeline/segment catalog, classifications, contact sheets and thumbnails, registry, finals, manifests, QA reports, dashboard, source metadata, code/tests/skills/config. Rebuilds `index.html` (self-contained dashboard: source info, status, counts by format, a card per video with thumbnail, title, format, duration, source timestamps, rank count, QA, caption, cover title, accent color and a link to the MP4).
8. `content-report <run-id> --command "<exact command>"` is the ONE final report. Then STOP and wait.

## Completion boundary
Authorized without asking: local processing, QA, organizing, registry updates, recoverable Trash cleanup of allowlisted files. NOT authorized: credits, uploads, TikTok transfer, public publishing, permanent deletion, source purging.
